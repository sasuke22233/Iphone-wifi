# 🤖 Бот магазина донат-товаров для Playerok

Бот автоматически общается с покупателем в чате [Playerok](https://playerok.com),
принимает доступ к игровому аккаунту **от самого покупателя по его оплаченному
заказу**, заходит на этот аккаунт и выполняет покупку/зачисление донат-товара
(UC, алмазы, кристаллы и т.п.).

```
Покупатель                 Бот                        Игровой магазин
   │  «привет, купил 660 UC»  │                            │
   │─────────────────────────▶│  авто-диалог: подтверждение │
   │  «да»                     │  заказа, запрос доступа    │
   │─────────────────────────▶│                            │
   │  «логин: … пароль: …»     │                            │
   │─────────────────────────▶│  заход на аккаунт ────────▶│
   │                           │  покупка доната ──────────▶│
   │  «✅ Готово!»              │◀───── чек/зачисление ─────│
   │◀─────────────────────────│                            │
```

> ⚠️ **Важно.** Инструмент предназначен для автоматизации **вашего магазина**:
> выдачи товара, который покупатель уже оплатил, на **его собственный** аккаунт
> с его явного согласия. Не используйте бота для чужих/украденных аккаунтов и
> мошенничества — это незаконно. Автоматизация чатов Playerok и входов в игры
> может противоречить правилам площадок — используйте на свой риск, с
> человекоподобными задержками и без спама.

---

## ✨ Возможности

* **Авто-диалог (FSM)** на русском: приветствие → подтверждение заказа →
  запрос доступа → запрос 2FA-кода (если игра потребует) → статус → итог,
  напоминания «зависшим» покупателям, отмена заказа по просьбе.
* **Приём доступа** в любом формате: `логин: x пароль: y`, `x:y`, `x y`,
  `user@mail.ru:pass`, отдельными сообщениями; одноразовые коды — `123456`.
* **Выдача заказа**: заходит на аккаунт покупателя и проводит покупку
  донат-товара через плагины-адаптеры (мок, универсальный web-сценарий).
* **Безопасность секретов**: пароли живут только в оперативной памяти,
  стираются сразу после заказа (или через TTL), маскируются в логах
  (`pl***r1`, `password=***`), никогда не пишутся на диск и не отправляются
  никуда, кроме логина самой игры.
* **Площадка**: мок/терминал для разработки и живой Playerok через Playwright
  (селекторы настраиваются в конфиге).

## 🚀 Быстрый старт

Ядро — чистый Python 3.11+, без зависимостей.

```bash
cd playerok_bot

# 1. Полный демо-диалог с симуляцией захода на аккаунт и покупки:
python demo.py

# 2. Поиграть самому: вы пишете как покупатель, бот отвечает:
python run.py --mock

# 3. Тесты:
pip install -r requirements-dev.txt && python -m pytest tests/ -q
```

## ⚙️ Настройка под свой магазин

1. Скопируйте конфиг и заполните товары:

   ```bash
   cp config.example.toml config.toml
   ```

2. `[[products]]` — ваши донат-товары. Ключевое поле `credentials_mode`:
   * `login` — достаточно ID игрока (часто пополнение по ID);
   * `login_password` — логин + пароль;
   * `login_password_otp` — ещё и одноразовый код (2FA).

3. Адаптер выдачи `adapter`:
   * `mock_game` — симуляция (для проверки диалога);
   * `web_game` — реальная покупка в магазине игры по TOML-«рецепту»
     (см. [`recipes/example_game.toml`](recipes/example_game.toml)).

   Рецепт — последовательность шагов браузера: `goto`, `fill`, `click`,
   `wait_for`, `assert_text`… Плейсхолдеры `{login}`, `{password}`, `{otp}`,
   `{quantity}` подставляются автоматически. Положите файл в `recipes/`
   под именем `<id-товара>.toml` или `<игра>.toml`.

4. Живой Playerok (`driver = "playerok_web"`):

   ```bash
   pip install playwright && playwright install chromium
   python run.py --config config.toml
   ```

   * Зайдите в аккаунт **продавца** вручную один раз и сохраните сессию в
     `storage_state`-файл (Playwright `context.storage_state()`), укажите путь
     в `[marketplace.options]`. Учётные данные покупателей для Playerok
     **не нужны и не используются**.
   * Селекторы в `[marketplace.options.selectors]` может потребоваться
     подправить под текущую вёрстку Playerok — у площадки нет публичного API.

## 🧩 Архитектура

```
playerokbot/
├── models.py         # Order, Credentials (с маскированием), State, Action
├── parser.py         # извлечение логина/пароля/кода из текста покупателя
├── credentials.py    # in-memory хранилище секретов с TTL и авто-очисткой
├── templates.py      # шаблоны сообщений (переопределяются в config.toml)
├── dialogue.py       # FSM диалога + разбор намерений
├── orchestrator.py   # главный цикл: сообщения → ответы → выдача → итог
├── marketplace/      # площадка: mock/stdio и playerok_web (Playwright)
└── fulfillment/      # выдача: mock_game и web_game (TOML-рецепты)
```

Потоки: выдача заказа выполняется в фоновом потоке, поэтому бот продолжает
отвечать другим покупателям, пока «заходит на аккаунт».

## 🔒 Модель безопасности

| Мера | Как реализовано |
|---|---|
| Пароли только в RAM | `CredentialVault`, ничего не пишется на диск |
| Авто-очистка | стирание сразу после выдачи/ошибки + TTL (по умолчанию 30 мин) |
| Маскирование | `Credentials.__repr__` → `password=***`, логин `pl***r1` |
| Логи без секретов | превью сообщений `<данные доступа>`, фильтр `_NoSecretsFilter` |
| Только по заказу | доступ запрашивается только в чате оплаченного заказа |
| Честность | бот представляется автоматическим ассистентом, предупреждает о смене пароля |

## ❓ FAQ

**Почему покупатель должен присылать пароль?**  
Так устроена выдача на чужой (для продавца) игровой аккаунт: продавец заходит
на аккаунт покупателя и проводит покупку. Бот прямо просит использовать
временный пароль и сменить его после выдачи; пароль стирается из памяти сразу
после заказа. Если игра позволяет пополнять по ID — используйте
`credentials_mode = "login"`, пароль не нужен вообще.

**Можно ли подключить другие игры?**  
Да: любой TOML-рецепт для `web_game` (или свой класс-адаптер, см.
`fulfillment/base.py`) — без изменений ядра.

**Что если нужен живой оператор?**  
Бот сам передаёт сделку оператору при ошибках (`close_deal(success=False)`)
и пишет об этом покупателю.
